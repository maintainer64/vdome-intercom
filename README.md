# VDome Intercom

Личная веб-панель домофонов VDome: открытие дверей, автоматическое открытие
при входящем вызове, статусы устройств и камеры. Go-сервер и React/TypeScript
интерфейс с вкладками «Домофоны», «Камеры», «Журнал» и «Аккаунт».

Адаптер восстановлен по официальному Android-клиенту VDome 3.0.4r.
На реальном аккаунте подтверждены вход через МТС ID, список подъездов,
получение RTSP-видео и передача HLS через сервер. Автооткрытие при реальном
вызове пока требует проверки на оборудовании. Проект не связан с МТС.

## Быстрый запуск в Docker

```sh
git clone https://github.com/maintainer64/vdome-intercom.git
cd vdome-intercom
docker compose up -d
```

Откройте **http://127.0.0.1:8080**. Авторизация сохраняется в Docker volume
`vdome-data`; перезапуск контейнера её не удаляет.

Для другого порта укажите и адрес панели:

```sh
PORT=8081 VDOME_ORIGIN=http://127.0.0.1:8081 docker compose up -d
```

Для демонстрации без обращения к VDome и реальным дверям:

```sh
VDOME_PROVIDER=demo docker compose up -d
```

Введите номер из 10–15 цифр и код `000000`. Все устройства и кадры в демо
синтетические. «Имитировать вызов» проверяет режимы автооткрытия.

Обновление и локальная сборка:

```sh
docker compose pull
docker compose up -d
# Собрать из исходников:
docker compose up -d --build
```

### Образы

Реестр: `ghcr.io/maintainer64/vdome-intercom`.

| Тег | Назначение |
| --- | --- |
| `latest` | Последний стабильный GitHub Release |
| `0.1.0`, `v0.1.0` | Конкретный релиз |
| `dev-123` | Проверенная сборка PR №123, без изменения `latest` |

Архитектуры: `linux/amd64`, `linux/arm64`. Для PR-образа:

```sh
IMAGE_TAG=dev-123 docker compose up -d
```

Runtime содержит только Go-бинарник, статические файлы интерфейса и урезанный
FFmpeg для RTSP/HTTP → HLS. Node.js, Go toolchain, компиляторы, исходники,
тесты и браузеры остаются за пределами финального образа. FFmpeg собирается
из официального архива с проверкой SHA-256; подробности — [THIRD_PARTY.md](THIRD_PARTY.md).
Контейнер работает от UID 10001 с файловой системой только для чтения;
запись разрешена в volume с сессиями и временную память для HLS.

## Вход

1. Нажмите «Войти через МТС ID». Откроется официальный сайт МТС.
2. Пройдите авторизацию и скопируйте JSON-ответ с `keycloakTokenPair`.
3. Вставьте ответ в поле панели и нажмите «Подключить мой дом».

Сервер проверяет сессию через VDome и сохраняет access/refresh-токены.
Пароль МТС панель не принимает. Автоматический возврат с сайта МТС
пока не реализован. Прежний SMS API доступен в раскрывающемся блоке;
его работоспособность на сервере не подтверждена.

## Домофоны и автооткрытие

У каждой точки доступа — состояние связи, кнопка открытия и три режима:

- **Выключено** — открытие вручную.
- **Один вызов** — одна попытка при следующем новом входящем вызове,
  затем режим выключается.
- **Каждый вызов** — открытие при каждом новом вызове, пока включён режим
  и запущен сервер. Закрытая вкладка не останавливает автооткрытие.

Между командами — минимум 10 секунд. Вызовы в этот интервал пропускаются,
не откладываются. Старые, чужие, исходящие, отменённые и повторные вызовы
не вызывают открытия. Первая синхронизация после старта только запоминает
накопленные события. Допустимый возраст нового события — 30 секунд.

Одноразовый режим и идентификатор вызова записываются **до** отправки команды.
При неоднозначном ответе автоматического повтора нет. Принятая команда
не доказывает физическое открытие: для этого нужен датчик двери.
Режимы изолированы по аккаунту и точке доступа; выход и повторный вход
отключают их. Сессия панели действует до 30 дней.

Входящие вызовы обрабатываются через SIP INVITE по WebSocket. Постоянная
SIP-регистрация ещё требует проверки с реальным вызовом. Android также
получает параметры через push; FCM/MPS-приёмник не реализован.
Если платформе нужны временные параметры из push, текущего адаптера
для постоянного автооткрытия будет недостаточно.

## Камеры

Вкладка «Камеры» запускает эфир по кнопке. H.264 передаётся через
RTSP → FFmpeg → HLS без перекодирования и без звука. Запасной кадр
загружается один раз; повторный запрос — только по кнопке «Обновить кадр».
При уходе с вкладки эфир останавливается, полученный кадр сохраняется.

Запросы одинакового кадра объединяются и используют кэш на 10 секунд.
Списки устройств обновляются раз в минуту; SIP-события проверяются локально
каждые 3 секунды. При ошибке действует пауза 15–120 секунд; HTTP 429 учитывает
`Retry-After`. Чтение сегментов видео не ждёт фонового сетевого опроса.

На сервере максимум 4 одновременных потока. После 45 секунд без запросов
процесс завершается. При выходе потоки аккаунта останавливаются сразу.
Исходные RTSP URL и токены не попадают в API браузера или аргументы процессов:
FFmpeg получает их через stdin. HLS-файлы доступны только сессии владельца
и удаляются при остановке.

## Конфигурация

| Переменная | Значение / назначение |
| --- | --- |
| `VDOME_PROVIDER` | `live` по умолчанию; `demo` — полностью изолированная демонстрация |
| `VDOME_ADDR` | В контейнере `0.0.0.0:8080`; локально `127.0.0.1:8080` |
| `VDOME_ORIGIN` | Адрес панели в браузере, без завершающего `/` |
| `VDOME_WEB_DIR` | `web/dist` — каталог собранного интерфейса |
| `VDOME_VAULT_FILE` | `data/live.vault` — файл сессий |
| `VDOME_VAULT_KEY` | Необязательный отдельный ключ: 32 байта в Base64 |
| `VDOME_MEMORY_ONLY` | `1` — хранить сессии только до перезапуска |
| `VDOME_SIP_WS` | Необязательный подтверждённый WSS endpoint |
| `VDOME_SIP_REGISTRAR` | Необязательный подтверждённый SIP registrar |

Без внешнего ключа создаются `data/vault.key` и AES-256-GCM vault с правами
`0600`. Сохраняйте оба файла: новый ключ не расшифрует старую сессию.
Доступ к ключу и vault вместе позволяет расшифровать токены. В compose
они находятся в volume. Папка `data/`, дампы трафика и исходные APK исключены
из Git и Docker build context.

API браузера использует HttpOnly + SameSite=Strict cookie, проверку Origin
и заголовка для изменяющих запросов. Для доступа через домен задайте
`VDOME_ORIGIN=https://ваш-домен` и используйте HTTPS reverse proxy;
порт контейнера по умолчанию опубликован только на localhost.
`GET /healthz` проверяет работу HTTP-сервера, а не доступность провайдера.

## Разработка

Нужны Go >= 1.24, Node.js 24 и FFmpeg в PATH для камер. CI и Docker
используют Go 1.27.

```sh
cd web
npm ci
npm run build
cd ..
go run ./cmd/server
```

Панель доступна на http://127.0.0.1:8080. Для локального демо:

```sh
VDOME_PROVIDER=demo go run ./cmd/server
```

### Проверки

```sh
go vet ./...
go test -race ./...
cd web
npm run build
npx playwright install chromium
# Отдельно запустите демо на 8082 с VDOME_ORIGIN=http://127.0.0.1:8082
VDOME_E2E_URL=http://127.0.0.1:8082 npm run test:e2e
```

Go-тесты проверяют сессии, ротацию токенов, изоляцию аккаунтов, CSRF,
шифрование, SIP, дедупликацию вызовов, отсутствие повторов unlock и backoff.
Браузерные тесты на desktop/mobile проверяют вход, одноразовое автооткрытие
в демо, журнал, вкладки, ручное обновление кадра и остановку поздно
подключившегося потока. Они отказываются выполнять команды на live-провайдере.

### CI и релизы

- Push в ветку и PR: Go vet/race-тесты, сборка production-образа,
  проверка минимального runtime и преобразования синтетического H.264 в HLS,
  браузерные тесты на демо-контейнере.
- PR из этого репозитория после успешной проверки публикует только
  `dev-<номер PR>`. Fork PR проходят проверки без доступа на запись в GHCR.
- Опубликованный GitHub Release `vMAJOR.MINOR.PATCH` собирает образ
  **без запуска тестов**. Версия должна совпадать с `web/package.json`,
  а коммит тега — принадлежать `main`. Стабильный актуальный релиз
  обновляет `latest`; prerelease и старые релизы его не изменяют.

Порядок выпуска: дождаться зелёного CI в `main`, обновить версию при
необходимости и создать GitHub Release с соответствующим тегом.

## Протокол и ограничения

[Исследование протокола](docs/protocol.md) ·
[каталог 134 обнаруженных HTTP-операций](docs/protocol-catalog.json).
Каталог описывает найденные методы, а не полную реализацию всех сервисов.

Звук, телефонный разговор, WebRTC, push-регистрация, оплата, заявки,
чаты и счётчики не реализованы. Списки ограничены `limit=1000`, как в APK;
пагинация сверх этого пока отсутствует. Панель рассчитана на личное использование.
